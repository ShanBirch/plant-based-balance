# Replies to our public comments on other people's posts

Authorised 16 October 2026. Audit: native/canonical reservations contained 29 verified Instagram comments and two verified personal Facebook comments, each with a native comment ID. Existing proactive claim paths enforce lifetime post no-repeat; they do not represent an incoming comment reply. No dedicated reply capture/claim path existed. These counts are a point-in-time audit, not coverage of all native replies or delivery proof for this new lane.

## Owners and discovery

The SAME `balance-public-post-comments` worker owns Instagram replies as shan_n_sunny. The SAME `balance-facebook-public-post-comments` worker owns personal Facebook replies as shazbirch, using the existing shared local surface mutex. No second responder, MBS takeover of a personal profile, API sender, scheduler or DM enrollment. Balance own-post comments stay with the MBS public-comment contract; third-party-post replies never enter that lane.

At each existing wake, before new proactive comments, perform a bounded native notifications review in the worker's own tab and inspect at most ten exact verified outbound comment threads per segment, carrying cursor/last checked source across wakes. Only observed notification links or recorded verified parent receipts are entry points, not profile hunts. Read the parent post/media, original saved comment, exact incoming author/profile/text/time/native ID, expanded replies and any intervening human response. Record observed pending/held/skipped sources and actual scan boundary in the existing private cursor, including notification position and root-attempt cursor. Rotate through unreviewed parents rather than checking the newest ten forever. No native notification is proof of an unanswered reply until expanded source review. Like/reaction-only notifications, spam, bots, unrelated tags and natural closes need no response. Never claim full coverage from a bounded scan.

Prioritise genuine unanswered replies; answer a question or continue briefly and naturally in public. No sales pitch, fitness qualification, links, forced question or private information. Preserve all personal/dating/manual/human/client/opt-out/safety/media holds and active exact recipient claims. A recent verified original comment or earlier verified reply in this same chain does not itself forbid the reactive response; unrelated outreach, unanswered private conversation, unresolved actions and independent holds still do. A public reply author may differ from the post author: verify the actual person, never reuse the post author's identity/eligibility. No silent-person chase or unsolicited DM.

## Exact supported native path

The migration `outbound_comment_replies` adds service-role-only RPCs and a durable exact incoming-comment ledger, not a sending service. It reuses the existing platform run/tab ownership. Every future inbound gets a separate `UNIQUE(channel,inbound_comment_id)` reservation. Parent must be a verified original comment, or our verified reply in that original chain. Missing stable IDs or unsupported native Reply controls are precise technical holds; never relabel a comment as `ig_messages` or use proactive lifetime-post reservations to bypass it.

1. Acquire/renew the worker's ordinary existing run and tab. Facebook must additionally `surface.cjs acquire/check` and stay inside eight minutes, release before nine. Keep normal 25/28/30 walls and no new claims after minute25. The reactive scan still runs when proactive50 is reached; no new proactive work or capacity is created. Use an ordinary fresh daily segment with carried proactive counts, not a new quota.
2. Query the exact verified root in `ig_public_comment_attempts` or `fb_public_comment_attempts`. Retain exact `id`, `post_url`, `proof.native_comment_id` (or `proof.comment_id`). Freshly review full native/canonical eligibility, known linked cross-channel claims and unanswered private conversations. Do not infer identity by display name. Save native source screenshot privately and exact evidence.
3. Call `reserve_outbound_comment_reply(p_channel,p_run,p_tab,p_root,p_person,p_username,p_post_url,p_root_comment,p_inbound,p_parent,p_inbound_text,p_text,p_evidence)`. Channels are `instagram` or `facebook`; `p_username` is the actual lowercase Instagram reply author, or verified cross-channel handle for Facebook, otherwise SQL NULL. `p_person` is that Instagram handle or exact Facebook profile identity. `p_root` is the original verified attempt UUID; `p_parent` is the native comment of ours they replied to; `p_inbound` is the exact new person-authored comment ID. Evidence contains substantive `history_review`, `eligibility_review`, `authorization_source`, `native_source_screenshot`, fresh `reviewed_at`, and truthfully verified `history_complete`, `eligibility_clear`, `cross_worker_clear`, `expanded_replies_reviewed`, `unanswered`, `public_context_understood` true. Booleans record actual checks, never grant permission. Store exact returned reservation UUID before native input.
4. For Facebook mirror the returned reservation BEFORE input using `surface.cjs reserve-reply TOKEN INPUT_JSON_PATH`, with `id` the new database UUID, `root_attempt_id`, `recipient` exact incoming author's profile URL, `source` equal to `facebook:comment:<incoming ID>`, `inbound_comment_id`, `text`, private `evidence` path and `database_reserved:true`. This requires a confirmed original parent in the shared ledger and preserves other holds/recent touches. Missing mirrored parent or failure means stop, retain database reservation/no-repeat, never bypass. Keep `kind=public_comment,reactive_reply=true`; existing outreach guards therefore still protect the person and no Story quota/enrollment is added.
5. Immediately before ONE native Reply/Post, revalidate exact account, source/expanded replies, holds, both required ownership checks and any new inbound. Call `activate_outbound_comment_reply(p_run,p_tab,p_attempt,p_inbound,p_text,p_review)` with fresh complete review evidence. It validates exact tuple and consumes a one-use activation. New generic IG/MBS claims are atomically blocked for an active exact reply recipient; existing foreign claims block reservation/activation. Actual tool rejection remains binding. No native activation when anything is uncertain.
6. Submit once, then reload the exact thread once after optimistic posting settles. Capture painted screenshot, saved reply ID, exact public sender/text/post, incoming parent and timestamp. Call `reconcile_outbound_comment_reply(p_attempt,p_proof,p_verified)`. Verified proof requires `post_url`, `inbound_comment_id`, `reply_to_comment_id` equal to incoming ID, new `native_comment_id`, `sender`, `text`, `native_reload_screenshot`, `native_readback`, `observed_at`. Read back the exact row. For Facebook then use existing `surface.cjs confirm` with exact UUID/native proof. Replies are separate reactive receipts, never proactive50 credit.

Any reserved/activated/uncertain source is terminal no-repeat for sending. Preserve uncertainty after failure; do not change ID or text to retry. Read-only saved proof reconciliation can mark an uncertain activated receipt verified even after lease expiry; it grants no new sending right. Reconciliation never releases independent holds. Carry unresolved source and parent IDs across days/wakes. Record actionable new blockers once; healthy foreign ownership quietly defers. No real test comment/DM is authorised. Setup/rollback tests do not establish that notifications were scanned or a real reply delivered.
