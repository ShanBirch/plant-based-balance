# Native Story observation gate

Read `scripts/lib/ig-story-observation.js` and paste its definitions into the supported cua_repl session. This helper uses the bound tab API only; it does not acquire ownership, write a composer or send. Renew the native Instagram lease and verify surface ownership before calling it.

1. Resolve an exact native `/stories/<creator>/<numeric-id>/` link before drafting. When a tray-opened viewer exposes only the creator URL, use an observed neighbouring native preview link to obtain the target's exact URL. If necessary navigate to the previous creator without drafting, read the target preview, and reopen that observed exact URL. Never use the neighbour's ID, guess a URL or read hidden app/network state. If no exact link is exposed, skip this Story and continue.
2. Call `openInstagramStoryVideo(tab, openStory, exactHandle)` in one browser call. This includes Reply hydration, a bounded read-only wait for actual rendered video data, then native Pause with conditional single recovery. Never pause before loaded video readiness: Instagram can show pre-load Play, then auto-resume when data arrives. The helper verifies the exact Story did not advance while loading. Save its observation as `first`.
3. In the next browser call capture a direct `tab.screenshot({})`, then call `readInstagramStoryVideo(tab, exactHandle)` as `second`. Run `assessInstagramStoryVideo(first, second)`. Do not replace this independent read with the opening result. Loaded visible video, exact recipient/source, native Play/no Pause, paused media and stable source/time are mandatory. Hidden preloaded videos must not be used. If the opening read caught hydration but the second read is loaded and paused, allow one bounded new baseline: save second as first and take a third read in a later call. Both new reads must independently pass the complete gate; do not treat an unloaded first read as success. Changed source/recipient requires discarding old observations and fresh review, not this hydration recovery.
4. A passing result means ready for visual review only. Visually check the actual screenshot agrees with the controls and content. A screenshot still showing Pause is stale proof; capture once more and skip if disagreement persists. A black or spinner frame is not understood content, even with ready media. The helper rejects end-boundary video frames but cannot detect every black/ambiguous frame.
5. Use native Play to watch the actual sequence, capturing multiple direct screenshots with media times. Keep each call bounded and renew the lease before recovery. Freeze again with `freezeInstagramStory(tab)`, then repeat two independent state reads. Review enough sequence to understand the chosen observation. If audio is muted/unheard, record that and do not quote or describe speech. If the source advances, discard the old draft and observations as an activation basis.
6. Save a structured analysis: exact creator/Story ID, playback times observed, visible text, actual action/sequence, one concrete reply anchor, audio status, uncertainty and screenshot proof. A reposted montage is not proof the creator performed an activity. Resolve uncertainty by more native observation or skip.
7. Only after complete canonical/native history, eligible relationship, holds/client truth, daily capacity, cooldown and lifetime source checks pass, compose one short fresh grounded private Story reply. Use the existing exact Story action claim. Recheck the frozen source and recipient, fill the private Reply textbox, then call `ig_browser_action_owned` immediately before one native Send. Record activation before moving on. Native saved delivery without an echo is terminal attribution-pending/no-repeat. Never send another message to test attribution.

Static Stories retain the existing two-read creator/frame/Play and actual-image visual checks. The video helper does not label a static Story failed because it has no video.

One recipient's unresolved delivery reserves that person's daily slot and excludes that person. It does not stop the remaining verified capacity. If unresolved subject aliases exist, conservatively reserve every unresolved subject until deduplicated. Continue other candidates only when the evidence gives a bounded conservative capacity below twenty. A genuinely unbounded/missing ledger may block sends, but does not block read-only inventory or playback tests.

Persist viewer/ranked cursor and skips. Continue past recipient-specific holds, unavailable/unclear Stories, source recovery failures and unsupported reopening DMs. End only on a real inventory boundary, budget/time wall or surface-wide fault. Do not call a small checked sample inventory exhaustion.

## Validation

`node --test tests/ig-story-observation.test.js` checks exact source binding, hydrated media, independent reads, frame/time changes, paused controls and the end boundary. On 9 October live native testing reproduced delayed screenshot painting, recovered an exact numeric Story URL from a visible neighbouring preview, and verified loaded paused video at independent reads. A final black boundary frame was correctly unsuitable for composition. No new message was sent during that test; this is not end-to-end send verification.
